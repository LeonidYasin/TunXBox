Hysteria2: нестабильность, индикаторы и расследование

Наблюдение владельца и границы

Hysteria2 на физическом устройстве то передаёт трафик, то не работает, иногда скорость низкая. После исправления сертификата загрузка подписки работает. Корневая причина не установлена. Ошибка REALITY у TCP VLESS, XHTTP и этот QUIC/UDP сценарий — разные задачи. Linux TCP REALITY тест не подтверждает Hysteria2.

Это план R13 и открытое расследование, не реализованный непрерывный мониторинг или auto-failover. Нельзя обещать, что только обновление sing-box исправит нестабильность.

Понятные состояния и индикаторы

  • Сервис VPN запущен — отдельно от «Интернет через профиль проверен».
  • Живость: не проверено / проверяется / проверено с timestamp / деградация / ошибка / результат устарел. Отсутствие байтов при простое не означает ошибку.
  • Последняя безопасная причина: QUIC/TLS/auth/timeout/DNS/routing/physical-network, только при наличии доказательства из ядра. Иначе честный unknown.
  • Последний RTT, вариация задержки и доля неуспешных HTTPS-проб; это не измеренная UDP packet loss.
  • Смена физической сети и количество/причина reconnect; debounce и manual stop должны сохраняться.
  • Скорость обычного трафика без активного теста; отдельный opt-in throughput test с раскрытыми destination, лимитом объёма/времени и отменой.
  • Компактный Phone/TV статус, фокусируемое раскрытие подробностей, ограничение частоты уведомлений, без блокирующего toast/dialog storm.

Диагностический pipeline

  • Проверка сгенерированных transport/TLS/SNI/ALPN/obfuscation параметров без раскрытия значений секретов.
  • Определение доступной физической сети и отдельная фиксация её потери/смены.
  • Ограниченный по времени handshake/HTTPS через выбранный профиль. Не менять профиль, транспорт или TLS verification молча.
  • Явно разрешённая серия коротких проб, история bounded и monotonic timing, безопасный outcome. Нельзя выводить скорость из нулевых счётчиков при простое.
  • Ручной экспорт whitelist: app/core/commit/build, coarse network type, длительности/количество попыток, классификация ошибки. Без names/URL/IP/UUID/password/raw logs, без автоматической отправки.

Что проверить на устройстве

Сравнить один профиль в одинаковое время с reference-клиентом. По отдельности Wi-Fi / мобильная сеть / Ethernet (если доступны), foreground/background, выключение экрана/возврат, смена сети, IPv4/IPv6. Записать время/длительность проблемы, build/commit, код диагностики, есть ли отказ обычного открытия сайтов, а не только тестового endpoint.

Не менять одновременно сертификат, MTU, obfuscation, DNS и transport: иначе нельзя определить причину. Не публиковать private subscription/ключи; сводку прислать по почте.

Definition of Done

Fixtures для blocked UDP, неправильной аутентификации, времени/цепочки TLS, DNS и медленного/нестабильного канала; точная категория или честный unknown. Ограниченность проб, отмена, отсутствие автоматического профайл-switch/TLS bypass, redaction tests, стабильный D-pad статус и физическая приёмка. Сначала диагностика, затем подтверждённое исправление; это gate следующего стабильного релиза, а не отмена текущей TCP REALITY проверки.
