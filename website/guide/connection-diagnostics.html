Сессия, ошибки запуска и отчёт на смартфон — кандидат R17

Отзыв владельца о rc.135: мгновенная скорость нулевая после теста, профиль/возраст/пояснения обрезаются; XHTTP отклоняется одним toast. Реализация поверх PR9, не в rc.135. До собственного полного CI и owner acceptance это кандидат.

Второй ряд ТВ

  • Сводка: имя активного (или выбранного при остановке) профиля; отдельные однострочные передано/получено из SpeedDisplayData.txTotal/rxTotal, не rate; отдельный короткий итог. При отсутствии callback — «—», не придуманный ноль. Название до двух строк, большие имена доступны в профиле; длинные объяснения и возраст не конкурируют с результатом за три строки.
  • Диагностика доступна и при остановленном ядре. Полный отчёт последней попытки: время, STARTUP/DEPENDENCY/RUNTIME/URL_TEST, код, whitelist протокол/транспорт/security, RTT при выполненном URL-тесте; реальные сведения APK/commit/CI/core/API/ABI и дальнейшие действия. Session counters текущие и только если известны. Дата отделяет сохранённую попытку от текущих счётчиков. Повтор URL-теста — только при активном ядре и явном действии.
  • YouTube при запущенном сервисе. Ни start, ни TCP, ни один URL не объявляются гарантией скорости/UDP/YouTube.

Счётчики идут из существующего core TrafficLooper, исключают bypass. URL-тест использует core connection tracker при наличии v2api; не добавлять оценочные байты ради ненулевой цифры. Если реальный обмен не отражается в totals, нужен отдельный runtime аудит, не косметическая подмена.

Ошибка до Connected

Сервис сохраняет типизированную причину ДО stop/state callback. UI открывает полный диагностический DialogFragment вместо только toast/snackbar для сообщения об отказе. Кнопки стандартного окна отделены от прокручиваемого текста; начальный фокус безопасный OK, не Share. Для XHTTP: NET_UNSUPPORTED, transport=xhttp, STARTUP; нет автоматической подмены на TCP. Добавление диагностики не добавляет поддержку XHTTP.

VPN работает в :bg: запись через существующий Room-backed configuration key-value, не SharedPreferences между процессами. Один bounded record до 1KB, сбрасывается при новом явном запуске, сохраняется после отказа/проверки. История всех сетевых пакетов не записывается. Classifier смотрит bounded error chain, но raw messages/logs не сохраняются. Некорректный/неизвестный формат не выдаётся за доказанную причину. Скрытые/фоновые UI не открывают окно автоматически; сохранённый результат доступен кнопкой.

Передача

Кнопка «Отчёт на смартфон» запускает отдельный opt-in listener:

  • частный IPv4 выбранного Wi-Fi/Ethernet, не VPN/cellular/0.0.0.0; если адресов несколько — явный выбор;
  • случайный 192-bit token в пути; только точный GET фиксированного TXT, ограничения размера/заголовков/таймаутов;
  • проверки Host/Origin, no-store/nosniff, нет wildcard CORS/доступа к файлам/импорта;
  • до 5 минут, Back/onStop/смена физической сети закрывают listener; нет тихого перезапуска передачи при возврате/повороте;
  • QR открывает скачивание в браузере смартфона; VPN телефона/изоляция Wi-Fi могут мешать;
  • HTTP не зашифрован: только доверенная сеть, никакого port forwarding. Облачный MCP/Telegram не используется.

Report whitelist содержит версии, протокол/транспорт/security, стадии, категории, RTT, известные counters. Нет имён профилей/серверов, IP endpoint, URL подписок, SNI, UUID, паролей, ключей, config dumps и сырых логов. «Полный» означает полный по доступным этапам/причинам, а не раскрытие конфигурации или утверждение о неисполненных probes.

Server адаптирован из ProxyDroid release 0f1c9bf15990 (GPL), attribution в source сохранён; Host/Origin защита добавлена. Compose UI не переносится: остаётся native TunXBox.

Проверки

  • JVM: whitelist/encode/decode/секреты, XHTTP stage, отдельные строки counters/result, окно startup error; loopback server exact token/Host/Origin/POST/close/expiry/size.
  • Android offline: синтетические totals при rate=0, реальный D-pad до Диагностики, безопасный отчёт, локальное QR/TXT скачивание и отключение ссылки без запуска VPN. Это UI/transport fixture, не доказательство throughput реального провайдера.
  • Rc.138: 235 JVM PASS; Android 4KB остановлен на устаревшем пути saved subscription report (3 Down/8 Right). Обновлён bounded обход динамических групп и catalog кнопок, assertions privacy/reachability/safe-close не удалены. 16KB нового кандидата обязательно.
  • Owner: установка поверх rc.135; реальный Hysteria traffic/counters; XHTTP full error; QR с отдельного телефона; 720p/1080p/large font/фон/сеть/close. Нули после настоящего обмена расследовать отдельно.

Коррекция по приёмке rc.143

Rc.143 прошла 245 JVM и по 15 Android/API35/4KB и API36/16KB тестов. Владелец нашёл проблемы на Android 9/32-bit: NET_OK 180 ms без счётчиков и долгое повторение без прогресса. Новый кандидат: выбранная группа первая (без изменения Room userOrder), отдельная строка прежних операций перед последней строкой «Все возможности». Исправляется регистрация callback по IBinder, а не по новым AIDL Proxy wrapper; DataStore default interval согласован с XML (1000 ms). Session totals считаются и при отключённом notification interval, без выдуманных байтов. Повторный Binder URL-вызов ограничен 8 s ожидания через один изолированный daemon worker; BUSY не создаёт новые потоки, отмена не останавливает VPN; показаны spinner, прошедшие секунды и deadline. Запоздалый результат не должен заменить новый timeout. Нужны новые полный CI и физическая приёмка; по одному NET_OK не обещать скорость/YouTube/UDP.
