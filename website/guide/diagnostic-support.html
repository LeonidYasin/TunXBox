Как сообщить о проблеме подписки или соединения

Доступность

В стабильной 1.5.0 и LAN rc.115 новых экранов сохранённой диагностики ещё нет. Ниже — поведение draft PR #5; устанавливать его можно только после отдельно опубликованной проверенной сборки. План и фактические проверки.

Безопасный минимальный отчёт

  • Укажите versionName/versionCode из «О приложении», Android API/версию, Phone/TV, модель устройства без serial/IMEI и способ управления.
  • Укажите этап: добавить подписку, обновить, импортировать отдельный профиль, запустить VPN или проверить доступ. Приложите ожидаемое и фактическое поведение, тип сети (Wi-Fi/Ethernet/mobile), время и частоту проблемы.
  • Для подписки в PR #5: Phone → Группы → меню нужной группы → «Диагностика обновления подписки»; TV → Инструменты → та же карточка для выбранной subscription group. Просмотрите сводку, затем явно нажмите «Поделиться этой сводкой». Открывается системный chooser, не автоматическая отправка разработчику. Можно скопировать текст в issue. Если записи нет, сообщите об этом — это не доказательство отсутствия профилей.
  • Укажите только семейства protocol/transport/security (например VLESS/TCP/REALITY или VLESS/XHTTP/REALITY), количество профилей, успешен ли TCP тест и отдельно успешен ли тест через VPN. Не вкладывайте параметры авторизации. Если Happ работает, укажите его версию и результат в той же сети, но не публикуйте рабочую ссылку.
  • Для воспроизведения создайте обезличенный минимальный fixture с нерабочими тестовыми credentials и адресами example.invalid/loopback. Он должен сохранять форму/названия значимых опций, но не реальные значения. Разработчик не должен запускать URL из отчёта без отдельного согласования.

Что не публиковать

  • Полные подписочные ссылки/QR, query/path tokens, UUID/password/private keys, Authorization/Cookie, реальные профили и резервные копии.
  • Raw logcat/neko.log без ручной проверки: старый экспорт логов ещё не имеет полного sanitizer. Новый whitelist report не делает старые журналы безопасными.
  • Скриншот с раскрытыми ссылками или QR. Обрежьте либо закройте их непрозрачным прямоугольником до публикации; одного размытия может быть недостаточно.

Whitelist сводка PR #5 включает APK/API/supported ABIs, время, этап/исход, длительность, фиксированный код и число сохранённых профилей при успехе. Это не лог трафика, не конфигурация и не непрерывная история. Отправка не даёт разработчику удалённого управления. Никакого бота/MCP upload по умолчанию нет.

Как читать результаты

РезультатЗначение / следующий шаг
SUB_TLS_TIMEСообщение похоже на expired/not-yet-valid certificate. Проверьте системные дату/часовой пояс и автоматическое время; если они верны — нужен действительный серверный сертификат. Не включать insecure как обычное исправление.
SUB_TLS_TRUSTПохоже на trust/SNI/hostname ошибку; проверить домен, цепочку сертификата и настройки сервера. Не отключать проверку TLS по умолчанию.
SUB_REALITYVerification error, не обычный ping. Сверить параметры с рабочим клиентом локально, не публикуя ключи/UUID. Точная причина ещё требует воспроизведения.
SUB_UNSUPPORTEDТранспорт не поддерживается builder выбранного ядра; переподключение не добавит поддержку. XHTTP пока не реализован.
SUB_DNS / SUB_TIMEOUT / SUB_HTTPПодсказка по исходной ошибке загрузки, а не доказанная причина всех последующих сетевых сбоев. Указать этап, сеть и время.
SUB_EMPTYПустой результат разбора: рабочая группа не должна быть заменена пустым набором.
SUB_CHANGEDНастройки группы изменились во время обновления; старый ответ не применён. Повторить после завершения редактирования.
SUB_LOCAL_SAVEПрименение БД не завершилось; транзакция откатывается. Нужен код/этап/версия, не содержимое профилей.
SUB_UNKNOWNНет подтверждённой категории. Не придумывать диагноз: сообщить воспроизводимые шаги и безопасные метаданные.

«Профили сохранены» не означает «туннель работает». TCP latency не подтверждает REALITY/TLS, DNS, UDP или передачу данных. Иконка VPN означает запущенный сервис, не гарантированный интернет. Целевой pipeline handshake/DNS/HTTPS и failover остаются отдельными задачами.

Разбор разработчиком

Сначала подтвердить точную сборку и этап. Затем offline parser/build fixtures → атомарность БД/отмена/параллельное редактирование → synthetic native protocol tests → physical-device acceptance. При воспроизведении не использовать секреты владельца в Git, Actions, artifacts или публичных issues. Серверные и клиентские ошибки разделять по доказательствам, не по тому, что другое приложение показывает Connected.

Следующая итерация после rc.117 (awaiting CI/publication)

Для отсутствия трафика проверять отдельную операцию: Phone → нажать статус подключения; TV → статус соединения → проверить действующее подключение. Новый structured report выдаёт NET_TLS_TIME/NET_REALITY/NET_CLOSED/NET_REFUSED/NET_NETWORK/NET_TIMEOUT и другие фиксированные категории. Причина показывается постоянным окном, не только toast. Перед запуском проверки статус честно говорит «доступ не проверен». Используется текущий настроенный test endpoint через работающее ядро, одна явная проверка до 3 секунд; при отсутствии ядра прямой тест не делается. Ошибка обновления подписки остаётся SUB_* и не выдаётся за диагноз VPN. EOF/reset — наблюдаемый симптом, не доказательство цензуры, неисправного сервера или клиента. Unknown остаётся unknown, если нет известного признака. Не отключать TLS для получения зелёного результата.

Быстрый профиль: меню добавления → «Прокси шлюза:10808» → определить текущий шлюз → подтвердить протокол/локальную группу → сохранить. Повторное действие обновляет только адрес управляемого профиля этого типа в выбранной группе; существующие ручные профили не принимаются под управление. Пароли/имя/другие опции управляемого профиля при обновлении адреса сохраняются. При смене сети действие читает её адрес заново; если несколько сетей/шлюзов — выбрать явно. Нет автоматического переподключения или изменения активного профиля.

Аудит закреплённого sing-box aed32ee3: boxapi CreateProxyHttpClient использует DialContext, который берёт box.Outbound().Default().Tag() и вызывает detour этого outbound. Новый service report обязательно передаёт non-null running box. Это проверка default outbound ядра, не гарантия маршрута каждого Android-приложения/TUN правила.
