## Основной путь

Раньше для явной проверки перед YouTube: подключиться → открыть статус → запустить тест → открыть YouTube: **4 OK**, плюс перемещения/первое согласие Android. Новый кандидат: подключиться → автоматический результат → YouTube: **2 OK**. Это модель подтверждений при уже выбранном профиле, не доказательство всех физических D-pad путей. Ошибка не открывает обязательный modal и не крадёт фокус.

## D-pad и порядок

- Верхний ряд: подключение → группы → добавить → обновление приложения → Phone; начальный фокус и стабильные IDs сохранены.
- Следующий ряд: профиль + накопленные байты сессии + краткий итог → Диагностика → YouTube (когда сервис запущен). Из Connect: Down к сводке, Right к диагностике, ещё Right к YouTube при исходной колонке 0, затем к плитке автопереключения (opt-in; открывает список профилей с чекбоксами и не меняет подключение сама). Плитка диагностики показывает текущий результат, возраст URL-проверки и скорости; полный отчёт доступен по OK. Проверить на 720p/1080p и больших шрифтах.
- Выбранная группа идёт первой среди групп, остальные сохраняют пользовательский порядок. Каждая группа — отдельный ряд: проверка и ранжирование группы по OK, затем её профили или добавление в пустую группу. Все группы доступны без переключения фильтра; длинный список прокручивается вертикально, не обязан помещаться целиком на экран.
- После групп отдельная строка операций: действия профиля, обновление и диагностика подписки, тесты группы, Home, импорт, перезапуск и закрытие. «Все возможности» — строго последняя строка: общая кнопка и отдельные кнопки каждого доступного раздела TvFunctionCatalog. Updater открывается одной OK-кнопкой без промежуточного каталога.

## Следующая оптимизация (не реализована этим графом)

Собрать редкие Home/restart/close и отчёты в один список «Ещё», убрать дубли импорта без потери методов, прямой updater уже есть в верхней строке. Сравнить частые и редкие сценарии: OK, D-pad, диалоги, возврат Back, focus stability, error recovery. Не уменьшать клики удаления ценой подтверждения и не скрывать ошибки. Все функции полного [каталога](features.md) должны оставаться достижимы.

## Критерии регулярного review

После каждого UI PR обновлять JSON/граф, CI coverage/confirmation budget и реальные скриншоты/DPAD smoke. Проверять выбранный/активный профиль, offline/failure/no profiles, смену сети, отмену, YouTube return, installer return. Граф не утверждает готовность runtime функций до CI и device acceptance.
