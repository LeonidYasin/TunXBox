# Постоянная подпись и обновление TunXBox

## Почему старые сборки требовали удаления

Сертификаты APK сборок 60627b22, 53a29ce5 и 3ee6f2fc различаются. CI-кэш `~/.android/debug.keystore` не сохранялся: в логах была ошибка отсутствующего пути. Проверка `apksigner verify` подтверждала корректность отдельного APK, но не постоянство ключа между сборками. Android не разрешает обычное обновление приложения с другой подписью.

## Одноразовая настройка владельцем

Нужны Python 3, Java/keytool и GitHub CLI (`gh`) с административным доступом к этому репозиторию. Команды выполняются на компьютере владельца, не в чате. Вход через `gh auth login` проходит в собственном браузере; пароли и токены не нужно сообщать агенту.

В checkout ветки `feature/tv-remote-support`:

```bash
gh auth login
python3 buildScript/setup_signing.py
```

Скрипт:
- создаёт один постоянный ключ в приватном каталоге `~/TunXBox-signing-backup` (права 700/600);
- сохраняет JSON-bundle только в GitHub Actions Secret `TUNXBOX_SIGNING_BUNDLE`;
- записывает только **публичный** SHA-256 сертификата в `signing-certificate.sha256` на ветке PR;
- не печатает приватный ключ/пароль, не передаёт их аргументами командной строки и не коммитит их;
- повторно использует исходный offline-backup; отказывается создавать новую идентичность поверх существующего секрета/публичного pin.

Нужно сохранить backup в защищённом offline-хранилище. Без приватного ключа обновлять приложения, подписанные этим сертификатом, невозможно. Не загружать backup/bundle в GitHub Files, issues, release assets, gist или чат.

## Резервная копия после настройки через защищённый браузер

Если ключ создан агентом и уже сохранён в Actions Secret, повторно запускать bootstrap для создания нового ключа не нужно. Владелец должен сохранить исходную идентичность, а не заменить её.

1. Задать отдельный сильный пароль (не пароль GitHub), минимум 16 символов, в repository Actions Secret `TUNXBOX_BACKUP_PASSWORD`.
2. До мержа workflow `signing-backup.yml` запускается при создании/изменении своего файла в ветке PR; после появления в default branch доступен и ручной запуск. Он шифрует backup в памяти через OpenSSL AES-256-CBC/PBKDF2 (200000 iterations), проверяет расшифрование и загружает **только зашифрованный** artifact с retention 7 дней.
3. Скачать artifact `TunXBox-encrypted-signing-backup`, проверить SHA256 и хранить архив offline. Пароль сохранить отдельно в менеджере паролей. Не публиковать архив или пароль.
4. Для восстановления на своём доверенном компьютере с OpenSSL:

```bash
openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 -in TunXBox-signing-backup.tar.enc -out TunXBox-signing-backup.tar
tar -xf TunXBox-signing-backup.tar
```

OpenSSL сам запросит пароль. Восстановленный `signing-bundle.json` содержит приватный ключ и пароли: хранить с ограниченными правами, не коммитить. Проверить публичный fingerprint; восстановить тот же bundle в `TUNXBOX_SIGNING_BUNDLE`. Шифрование здесь предназначено для приватной offline-копии; checksum защищает от случайной порчи, не от злонамеренной замены. Не расшифровывать полученные от посторонних архивы.

## Первое опубликование после настройки

Для **первого перехода со старых временных ключей** запустить `prerelease-from-pr.yml` на ветке PR с `allow_legacy_signer_migration=true`, `check_only=false`. Это не обход Android: старые APK потребуют один раз экспортировать/сохранить данные, удалить старую установку и установить новую. Обычные дальнейшие публикации используют `allow_legacy_signer_migration=false`.

Перед удалением сохранить профиль/подписку и, при необходимости, полный backup через «Все возможности» → «Инструменты» → «Резервная копия». LAN-импорт переносит профили, а не все глобальные настройки.

## Автоматические проверки

- `applicationId` остаётся `com.tunxbox.app`.
- Публичный pin сверяется с настоящим сертификатом keystore, затем с сертификатами каждого APK из `apksigner --print-certs`.
- APK metadata читается из `aapt`, а не предполагается по названию файла.
- Preview `versionCode = VERSION_CODE * 1000000 + github.run_number`; обычный release зарезервирован выше preview той же версии. При переходе к следующей версии metadata база растёт.
- Все ABI-варианты имеют одну application/signing/version identity.
- Повторная публикация старого run/той же версии и произвольная смена сертификата запрещены. Разрешение legacy-миграции не допускает смены уже закреплённого сертификата.
- Если секрет/pin отсутствует, публикация запрещена. `check_only=true` проверяет код и metadata, но **не публикует** временно подписанные APK и не выдаётся за готовый релиз.
- Приватные временные файлы `.signing` исключены из git и удаляются в конце job.

## Что ещё требует проверки

- Установить два последовательных APK с новым постоянным сертификатом через Android installer без удаления и убедиться, что профили/настройки сохранены.
- Проверить реальный пульт, TV-прошивку и VPN: JVM-тесты не запускают JNI/Go и не имитируют системную установку приложения.

## Информативные имена новых APK

Имя новых файлов строится из фактических `versionName` и `versionCode`, прочитанных из подписанного APK, а не только базовой версии/taga. Формат: `TunXBox-{installedVersionName}-android-tv-phone-{ABI}-{flavor}-release-vc{versionCode}-g{shortCommit}.apk`. Например, `TunXBox-1.6.0-rc.120-android-tv-phone-universal-preview-release-vc48000120-gfe912123.apk` — пример формата, не переименование ранее опубликованного файла. Номер RC должен совпадать с build sequence в versionCode; universal означает фактические четыре ABI. `preview-release` — тестовый канал, но подписанная release-сборка, не debug. Stable использует фактическую версию без RC и `oss-release`.

Для rolling RC публикация сверяет имя файла/manifest/SHA256SUMS, Assets label/name, URL и реальный HTTP `Content-Disposition` после redirects. Заголовок release page показывает установленную версию с номером RC. При расхождении проверка падает; стабильные ранее опубликованные Assets не переименовываются. Имена APK не содержат ключей или данных подписки.

## Native updater R10

[Реализация-кандидат, ограничения и приёмка](app-updates.md): выбор stable/test в меню, приватная докачка, реальный signer/ABI/package/version/hash и Android installer. Не обходить несовпадение подписи удалением приложения; личные ключи никогда не передаются updater. Старый stable не понижается поверх более нового test code.


## Подписанный кандидат только для проверки на устройстве

`prerelease-from-pr.yml`: ручной запуск на ветке с нужным кодом, `artifact_only=true`, `check_only=false`, `recover_rc158=false`, `allow_legacy_signer_migration=false`, `ref` оставить пустым. Новый режим не переносить на старый workflow без этого input. Он выполняет полный Preview compilation/JVM/два named19 emulator gates, затем загружает существующий pinned bundle, проверяет реальные APK signer/package/version/ABI/16KB alignment и обновление относительно manifest опубликованного rc.158. Никакие signing secrets в artifacts не включаются.

Результат — Actions artifact `TunXBox-android-preview-release-{actualSHA}`: три подписанных APK, manifest и SHA256SUMS, retention30дней. Это не GitHub Release, не stable, не автоматическая установка и не подтверждение реальной приёмки. Public/rolling tags и assets не изменяются; recovery job и release/PR-publication steps исключают artifact-only. `check_only=true` по-прежнему не использует private signer и не выдаёт installable signed release. Ошибка обязательного gate блокирует artifact upload; режим не обходит failed emulator tests.

Первый baseline — установленный владельцем rc.158; если на устройстве другая/новее сборка, дополнительно сверить фактические versionCode и signer перед установкой. Не удалять приложение при конфликте подписи: сначала разобраться. Изменения приложения в тестовом кандидате остаются PR17, runtime данным workflow не меняется. Версия RC получается из фактического run sequence; её нельзя заранее объявить собранной/прошедшей проверки.

Приёмка: смартфон владельца — штатное обновление и сохранность профилей/настроек, portrait scroll, VPN/selected profile не меняются сами, full TXT действительно сохранён. ТВ/приставка владельца — RU/EN, 720p/1080p где доступны, normal/large font, D-pad/Back/Close и полный текст; камерой телефона считать short QR с экрана ТВ и получить текст. Если ТВ недоступен, отметить TV/camera acceptance PENDING, не засчитывать эмулятор вместо устройства. Модели/Android/текущую версию выяснить у владельца, не угадывать.
