# Как поддержать TunXBox

Публичная почта владельца: [leonidyasin@gmail.com](mailto:leonidyasin@gmail.com). Telegram: [@LEONI_YA](https://t.me/LEONI_YA). [GitHub Issues](https://github.com/LeonidYasin/TunXBox/issues) включены; бесплатная обратная связь доступна там, по почте и в Telegram. Discussions отдельно не проверены. Не отправляйте секреты в публичный репозиторий.

| Способ | Полезный результат |
|---|---|
| Тестирование | Модель/Android/ABI, версия и commit APK, точные шаги, ожидаемый/фактический результат; приёмка Phone/TV, пульта, обновления поверх старой версии |
| Баг-репорт | Копируемая безопасная сводка и диагностический код; без подписок, UUID, паролей, персональных endpoint и raw logs |
| Код | Небольшой отдельный PR от актуального master, тесты/документы, отсутствие приватных fixtures; no silent TLS bypass/failover |
| Go и стандарты | Проверенная матрица protocol/transport/core, pinned обновления, 16KB/ABI/JNI regression tests; импорт ссылки не доказательство работы |
| Переводы | Проверенные строки и смысл ошибок, длинные подписи на TV, доступность и отсутствие устаревшего брендинга |
| Документация/UX | Короткие сценарии, читабельные схемы, D-pad focus, размеры элементов и контраст; отличать implemented от planned |
| Сообщество | Помощь новичкам, демонстрации, обзоры и проверенные ссылки на настоящий проект; без обещаний анонимности/универсальной совместимости |
| Оборудование/инфраструктура | Согласованное тестовое устройство, воспроизводимый публичный fixture, помощь с CI; без передачи production root/key или скрытой телеметрии |
| Безопасность | Чувствительные уязвимости сначала по почте, без публичного exploit/секретов; bounty не обещан |
| Финансовая поддержка | Разовая помощь, регулярное спонсорство или бюджет конкретной задачи — обсудить по почте; актуальные реквизиты не опубликованы, автосписаний нет |
| Коммерческие услуги | Отдельно согласуемая диагностика, исправление или сопровождение; [проект условий](support-services-proposal.md), не действующая оферта |

Не требуется платить, чтобы сообщить об ошибке. Оплата не покупает молчание об уязвимостях, не ограничивает GPL и не гарантирует исправление всех багов. Рекламу/партнёрства обсуждать отдельно с прозрачной маркировкой и без доступа партнёров к профилям/трафику.

Перед вкладом: [архитектура](architecture.md), [разработка](development.md), [безопасность](security.md), [roadmap](roadmap.md). Авторизация владельца на merge относится к конкретному PR, не ко всем будущим изменениям.
