# Названия подписок и строковый ТВ-интерфейс — кандидат R16

Отдельная ветка `feature/tv-groups-subscription-names`, поверх PR8. Эти изменения **не входят в rc.135**; до завершения собственного CI и проверки владельцем это кандидат, не принятый redesign.

## Имя подписки

Общий RawUpdater для TV и Phone раньше учитывал только `Content-Disposition`, и только для автоматически созданного имени. Добавлено чтение метаданных:

1. `Profile-Title`: обычный UTF-8 текст или `base64:`.
2. `Content-Disposition`: `filename*` UTF-8 (RFC5987), затем `filename`.
3. Явное название коллекции в JSON (`profile-title`, `title`, `remarks`, `name`) или комментарий `# profile-title:`. Это fallback только при отсутствии пригодных заголовков.
4. При отсутствии метаданных остаётся прежнее имя; название первого сервера не используется как имя подписки.

Автоматически заменяется только пустое имя или точный шаблон `Subscription #<цифры>`. Имя из `sn/clash ?name=` и ручное переименование сохраняются. После первого успешного присвоения имени оно не обновляется произвольно при следующих загрузках. Для уже автоматически названной группы достаточно обновить подписку; повторный импорт не требуется. Атомарное применение подписки сохраняет конкурентное ручное переименование, существующие профили и прежние данные при неудаче.

Метаданные недоверенные: управляющие символы очищаются, строка ограничена 128 Unicode-кодпоинтами, некорректные Base64/UTF-8 игнорируются без срыва импорта. Нет новых диагностических записей с URL/ключами, внешнего resolver или автоматической отправки данных.

## Строки ТВ

1. **Главная**: подключение/отмена/отключение, группы, добавить, Phone. Начальный фокус на подключении; порядок сохранён.
2. **Подключение и диагностика**: компактный результат автоматической проверки, затем YouTube при запущенном сервисе. Полные подробности открываются явно.
3. **Каждая имеющаяся группа отдельной строкой**: карточка выбора группы, её профили или добавление в пустую группу. Группы и профили следуют установленной сортировке. Не нужно предварительно переключать группу, чтобы увидеть другие.
4. **Все возможности**: общая кнопка каталога, отдельные кнопки каждого доступного раздела того же `TvFunctionCatalog`, затем действия профиля/подписки, тесты и системные действия. Dashboard/Play ограничения сохраняются. Это прямые кнопки разделов, а не 224 настройки и 17 редакторов, одновременно развёрнутые на главном экране.

Все строки присутствуют в главном списке, но много групп не могут физически помещаться одновременно на любой экран: используется вертикальная прокрутка, внутри строки — горизонтальная. Следующий шаг после измерений — якоря/секции при необходимости, а не обещание нулевых кликов.

Выбор группы меняет только контекст просмотра/импорта, **не переключает VPN**. Выбор профиля другой группы обновляет выбранные группу и профиль, но не перезапускает активный туннель без явного подключения. Выбранный и активный профиль различимы. Строки, карточки и фокус имеют стабильные, разделённые пространства идентификаторов; обновление счётчиков не должно пересоздавать всю навигацию.

## Проверки до merge

- Метаданные: plain/Base64 UTF-8, RFC5987, отсутствие названия, ошибочные данные, длинные имена/управляющие символы, ручное имя и атомарный concurrent rename.
- JVM/Robolectric: карточка группы, очистка выбранности при переиспользовании, отсутствие коллизий ID группы/профиля/empty hint, отдельные фокусируемые кнопки всех разделов каталога.
- Source-linked [граф](tv-navigation.md): порядок строк и direct updater, покрытие текущих действий, отсутствие VPN-команды при выборе группы.
- Offline Android smoke на 4KB/API35 и 16KB/API36: все группы в adapter, реальный D-pad до новой пустой группы, выбор и импорт без изменения VPN. Не использовать приватную подписку как CI fixture.
- Физический ТВ: 720p/1080p, большой шрифт, 1/3/10 групп, длинные названия; все группы доступны, Back и возврат из updater восстанавливают фокус; обновление и удаление группы не оставляют focus trap.
- Установка подписки TV и Phone: название провайдера при наличии метаданных, сохранение ручного имени, прежние профили при неудаче. На экране не путать доступный TCP-порт/запущенный сервис с проверенным Интернетом.

Полный CI, опубликованный APK с проверенной подписью и ручная приёмка владельца обязательны. PR8 и R16 не мержить автоматически.

## Версия на стартовом экране и About

Согласованная окончательная схема: **ровно три карточки** — «TunXBox · установленная версия / что нового и проверить» → ТВ с пояснением → смартфон с пояснением. Верхняя карточка компактнее; фокус при запуске на последнем выбранном режиме, не на приветствии. При первом запуске без сохранённого выбора учитывается тип устройства. Up открывает доступ к выпуску без дополнительного обязательного OK при обычном входе в режим.

Верхняя карточка открывает отдельный `ReleaseNotesActivity`: изменения, список проверок, известные ограничения — из ресурсов именно этого APK, без запросов к GitHub и без Интернета. Заголовок использует фактический BuildConfig.VERSION_NAME; versionCode/commit/CI отображаются внутри сведений, а не загромождают главный экран. Кнопка «Полные сведения о программе» открывает существующий About, включая ядро/полный commit/run ID/контакты/GPL. Back из About возвращает к сведениям с фокусом на кнопке; Back из сведений возвращает к верхней карточке выбора режима. Ни один из этих переходов не выбирает режим, не изменяет selectedProxy и не отправляет VPN-команд.

Контент выпуска обновлять вместе с изменениями source; встраивание не означает автоматическое составление release notes по GitHub. При новом релизе review должен проверить актуальность обоих переводов. Большой текст прокручивается D-pad, каждый блок имеет доступный фокус. При наличии подтверждённой package-replacement отметки сообщение об установленном обновлении видно уже на launcher, до выбора TV/Phone.

Rc.137 отменена до публикации, чтобы не предлагать устаревшую схему с четвёртой кнопкой About. Новый полный CI обязателен: три карточки/начальный фокус/переходы и реальный D-pad по блокам/возврат проверяются JVM и Android; App metadata export=false, исходные 4KB/16KB gates сохраняются.

Rc.136 не опубликована: 233 JVM cases, 1 failure — старый тест использовал индекс строки инструментов и попал в динамическую строку профилей. Исправлен поиск по стабильному row ID; сохранены assertions начального Connect и последних restart/close, добавлена проверка последней позиции инструментов. Traffic guard теперь наблюдает все строки кроме connection, включая все группы. Новые launcher JVM/Android cases должны пройти полный CI; тесты не отключаются.

Системный установщик контролируется Android/OEM. MY_PACKAGE_REPLACED + разрешённое уведомление могут предложить «Открыть», но принудительный background Activity launch не используется. При обновлении со старого updater без expect-marker новая версия не может восстановить отсутствующую отметку; версия на launcher работает независимо от неё. Возврат на Home сам по себе не доказывает FATAL EXCEPTION.


### Коррекция по приёмке rc.143

Rc.143 прошла 245 JVM и по 15 Android/API35/4KB и API36/16KB тестов. Владелец нашёл проблемы на Android 9/32-bit: NET_OK 180 ms без счётчиков и долгое повторение без прогресса. Новый кандидат: выбранная группа первая (без изменения Room userOrder), отдельная строка прежних операций перед последней строкой «Все возможности». Исправляется регистрация callback по IBinder, а не по новым AIDL Proxy wrapper; DataStore default interval согласован с XML (1000 ms). Session totals считаются и при отключённом notification interval, без выдуманных байтов. Повторный Binder URL-вызов ограничен 8 s ожидания через один изолированный daemon worker; BUSY не создаёт новые потоки, отмена не останавливает VPN; показаны spinner, прошедшие секунды и deadline. Запоздалый результат не должен заменить новый timeout. Нужны новые полный CI и физическая приёмка; по одному NET_OK не обещать скорость/YouTube/UDP.

## Меню группы и свёрнутые ряды (цикл 1.7.0)

После приёмки rc.164 выяснилось, что на ТВ не хватает управления самими группами: плитка группы только выбирала её и сразу запускала пинг, а изменить или удалить группу с телевизора было нельзя. Теперь первая плитка ряда открывает меню действий с этой группой.

### Что в меню

| Пункт | Условие | Что делает |
|---|---|---|
| Выбрать группу | группа не выбрана | Меняет только контекст просмотра/импорта, VPN не переключается |
| Проверить группу (пинг) | в группе есть профили | Запускает существующую проверку и ранжирование профилей |
| Обновить подписку | только подписки | Обновление через тот же updater, что и кнопка «Обновить» |
| Сортировка профилей | всегда | Порядок из подписки / по имени / по задержке; текущий вариант отмечен |
| Свернуть профили / Развернуть профили | всегда | Оставляет в ряду только первую плитку либо показывает все профили |
| Переименовать группу | всегда | Ручное имя сохраняется; пустое имя отклоняется |
| Удалить группу | всегда | Подтверждение с числом профилей; удаляются группа, профили и журнал подписки |

Порядок пунктов стабилен: сначала выбор, затем проверка/обновление, затем вид и сортировка, последним — удаление. Открытие меню само по себе ничего не выбирает и не переключает: старое поведение «OK = выбрать группу + сразу пинг» заменено явными пунктами, чтобы случайное нажатие не меняло контекст.

### Свёрнутые ряды

- Свёрнутая группа оставляет только первую плитку; заголовок ряда получает пометку «· свернуто», плитка — «Профилей: N · свернуто».
- Состояние хранится отдельно для каждой группы в `TvGroupViewPreferences` (ключ `tv_collapsed_groups`, стабильный список id) и переживает перезапуск; по умолчанию группа развёрнута, поэтому обновление не меняет привычный экран.
- При удалении группы её id забывается, чтобы настройка не росла бесконечно. Свёрнутость не влияет на доступные действия и не скрывает группу из выбора.

### Границы

- Удаление группы с активным профилем при работающем VPN отклоняется с подсказкой: сначала отключите соединение. После удаления выбранный профиль из этой группы сбрасывается, а выбор группы восстанавливается снимком.
- Сортировка меняет `ProxyGroup.order` (`GroupOrder`), то есть действует и на телефон; ручная перестановка профилей по-прежнему доступна только при исходном порядке — существующее ограничение, а не новое поведение.
- Перестановка самих групп выше/ниже в это меню не входит: выбранная группа всегда показывается первой, поэтому «выше/ниже» было бы двусмысленным. Это отдельный вопрос UX, если понадобится.
- Полноценные настройки группы из телефонного экрана (URL подписки, авто-обновление) не дублируются: меню ТВ покрывает частые операции, а не заменяет редактор.
