# Обновление TunXBox из приложения

## Статус и архитектура

Реализация R10 в отдельной `feature/in-app-updates` на принятой владельцем rc.130; это кандидат для CI и проверки на реальных Phone/TV, не обещание уже опубликованного APK. PR5/master/main автоматически не сливаются. Неизменяемый stable 1.5.0 не подменяется.

Меню **Обновление приложения** доступно в Phone и общем каталоге TV. Кнопки обновления в About ведут в тот же native экран. По умолчанию stable, тестовый канал выбирается явно. При открытии экрана ничего не скачивается. Последовательность: выбрать канал → проверить → скачать/продолжить → проверить APK → установить → подтвердить Android. Файл и полное имя выпуска показаны до установки. Проверка каталога не отключает VPN и не меняет профиль.

Изучен опубликованный [LocProxyTV v3.8.5 / ProxyDroid](https://github.com/LeonidYasin/proxydroid/releases/tag/v3.8.5-rc.ge976d8b2870a), точный commit `e976d8b2870ab1f906e955be07882f7334632b40`. Под GPL адаптированы ResumableDownload, ApkInstallIntents, SignaturePolicy и download fixtures; GitHubUpdater переписан под каталог, ABI и pinned подпись TunXBox. [Исходники reference](https://github.com/LeonidYasin/proxydroid/tree/e976d8b2870ab1f906e955be07882f7334632b40/app/src/main/java/org/proxydroid/update). Авторство и полный GPL проекта сохранены.

## Границы безопасности

- Только публичные GitHub Releases TunXBox: stable `/releases/latest`, test опубликованные prerelease. Источник — `apk-manifest.json`, не заголовок rolling релиза. Метаданные ограничены по размеру; HTTPS/redirect allowlist; никакого токена GitHub в APK.
- Подходящая ABI по предпочтениям Android: отдельный ARM APK перед universal. Проверяется реальное содержимое `lib/` APK, а не только имя. Полное имя файла, manifest и URL basename должны совпадать.
- Отказ при downgrade, чужом package, code/name, hash/размере/ABI, отсутствующей или другой подписи. Настоящие сертификаты установленного и скачанного APK сравниваются с pinned release identity; checksum сам по себе не заменяет подпись. Повторная установка того же code доступна только по явному действию.
- На Android 24+ проверяется реальный minSdk из APK. На API21–23 окончательное ограничение minSdk применяет системный установщик; не объявлять это полной собственной проверкой на старых API.
- Частичная загрузка в приватном `cache/update-downloads` с Range/retry и проверкой Content-Range. Если Range проигнорирован, загрузка начинается заново, не склеивается с префиксом. После hash/signature/package/ABI проверки APK перемещается в `cache/updates`.
- Отдельный FileProvider публикует только `cache/updates`; partial-файлы через него недоступны. Перед каждой попыткой установки кэш повторно проверяется. Разрешение read только для content URI; нет world-readable Downloads, silent install, NEW_TASK из Application.
- Пауза/уход в фон/закрытие экрана отменяют операцию. Сохранённые байты можно продолжить после проверки того же выпуска. Кэш может быть удалён Android; это не постоянное хранилище. Операции не продолжаются скрыто как background updater.
- Установка — ACTION_INSTALL_PACKAGE, fallback ACTION_VIEW для OEM/TV. Android26+ может потребовать разрешение источника. Возврат в видимый экран возобновляет явно начатую установку; неподдерживаемый OEM установщик показывает ошибку, не обходит защиту Android. TunXBox не утверждает успех установки лишь по запуску intent.

## Проверка владельцем после первого ручного обновления

Первый APK с updater придётся установить обычным способом: в rc.130 этого меню ещё нет. Новая сборка публикуется только после CI. Далее:

1. Сохранить число групп/профилей и текущую конфигурацию. Открыть меню на телефоне и ТВ; stable выбран, загрузка сама не начинается; пульт достигает канала/кнопок, прокрутка не перекрыта панелью трафика.
2. На тестовом APK выбрать stable: версия 1.5.0 должна быть отклонена как downgrade. Не удалять приложение.
3. Выбрать test → проверить: версия/code/commit/имя APK соответствуют выпуску. Скачать, прервать связь/поставить паузу, восстановить и продолжить; итоговый APK обязан пройти проверку. Ошибка соединения объясняется, непроверенная установка недоступна.
4. Нажать установить: системное разрешение и подтверждение; отменить и повторить. Можно явно переустановить текущий test APK для проверки пути без ожидания следующего выпуска.
5. После установки проверить About, сохранность групп/профилей, работу Phone/TV и подключения. Отдельно проверить последующее повышение versionCode и ARM32/ARM64/OEM. Эмулятор offline smoke не подменяет эти сценарии.

Автоматическое обновление ядра независимо от подписанного APK не включено. Периодический фон, тихая установка, подписки оплаты и диагностика на сервер не реализованы этим PR.
