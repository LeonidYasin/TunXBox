# Получение подписки по словарной фразе — R14

## Статус: дизайн, не готовый интерфейс

Задача владельца: вместо длинной секретной ссылки вводить удобные слова с пульта/телефона. Словарная фраза не восстанавливает произвольный URL сама: нужен доверенный resolver с mapping либо одноразовое локальное pairing с телефоном. Не использовать пароль панели 3x-ui или личный Telegram login; нет обещания совместимости с произвольным провайдером без сервиса.

## Рекомендуемый отдельный MVP

- Узкий HTTPS broker (можно рядом с MCP, но **не весь административный MCP API**). Адрес resolver один раз явно настраивается/подтверждается; не угадывается по словам. Сертификат валиден, TLS не отключается.
- Телефон/web с явным согласием создаёт случайный код: 6 слов из подготовленного словаря 2048 слов = 66 бит при равномерном CSPRNG. Словарь исключает путаницу/нецензурные слова; локализованный словарь должен сохранять энтропию. Не произвольная человеческая фраза, не короткий PIN и не долгоживущий bearer.
- TTL 10–30 минут, одноразовое погашение (атомарное), возможность отзыва. IP и глобальные лимиты, backoff; одинаковая внешняя ошибка неверного/просроченного кода. Phrase в POST body, не URL/query/логи/аналитика. Сервер хранит проверяемый hash кода, секретные URLs защищены отдельно, минимальная retention.
- Клиент получает URL после проверки фразы. Показать provider host без секретного пути, запросить подтверждение и выполнить обычный безопасный import/update pipeline. URL остаётся секретом. Разрешённые HTTPS провайдеры/redirect boundaries; не открытый proxy и не SSRF: лучше возвращать URL, не скачивать произвольные адреса сервером.
- Технические отчёты очищаются от фразы, URL/UUID/password/profile names. Никаких административных credentials, bot token или remote execution в APK. Публикация сервиса требует отдельного решения владельца о доверии, privacy, хранении и эксплуатации.
- Истечение/отзыв фразы не отзывает уже импортированные ключи. Для отзыва доступа менять subscription token и credentials на VPS отдельно.

Альтернатива: короткое словарное pairing с телефоном в доверенной LAN поверх существующего локального обмена. Обходится без облачного URL-хранилища, но требует общей сети/discovery и аутентифицированного одноразового pairing; не равнозначен доступу по фразе из любой сети.

## Acceptance отдельного PR

TV/Phone ввод, нормализация пробелов/регистра без снижения энтропии; expired/reused/wrong code; brute force limits; атомарный replay; сертификаты/redirect/SSRF; отсутствие секретов в логах/скриншотах/fixtures; подтверждение provider перед импортом; отмена/отзыв; реальный серверный lifecycle и миграция. Не добавлять кнопку, ведущую в несуществующий сервис.
