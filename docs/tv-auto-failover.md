# Автопереключение активного профиля — концепт failover

Концепт для цикла 1.7.0. Источники: [roadmap](roadmap.md) (R5 «Живость туннеля и failover», R13), [protocol compatibility](protocol-compatibility.md) (R5 failover после D1/D2/C1), [TV connection health](tv-connection-health.md).

## Суть концепта

Пользователь включает режим авто-переключения при проблемах с подключением и формирует список профилей, допускаемых к автоматическому выбору. При сбое или потере соединения текущего активного профиля система автоматически переключает его на лучший по пингу профиль из включённого списка.

## UX (для простого пользователя)

1. Плитка **«Автопереключение при проблемах с подключении»** — включение режима (opt-in).
2. Окно со списком всех существующих профилей; чекбоксы — участие в автовыборе; порядок списка — порядок авто-переключения.
3. При проблеме с текущим подключением — автоматически переключаем на лучший по пингу отмеченный профиль.

## Границы и безопасность

- Режим opt-in; ручной override важнее автоматического выбора.
- Cooldown / hysteresis; ограничение числа авто-переключений за сессию → стоп и ручная диагностика.
- Автовыбор только среди подтверждённо совместимых профилей; не «лечить» reconnect-ом ошибку сертификата или неподдерживаемый транспорт.
- Активный управляемый профиль останавливается перед сменой адреса (LAN gateway:10808), как требует существующий процесс.

## Механика (концепт)

- Триггеры: переход VpnService в disconnected / fail health-check / смена network epoch.
- Выбор: из включённого пользователем списка — лучший по пингу профиль, прошедший подтверждённый health check.

## Связь с существующим

- R5: end-to-end failover, cooldown/hysteresis, manual override, без reconnect loop.
- R13: persistent health/failover — bounded-реализация данного концепта.
- tv-connection-health: автоматическая ошибка ранее не меняла выбранный профиль; концепт вводит opt-in авто-переключение как отдельный режим.

## Следующий шаг

Концепт фиксируется; реализация (state machine + UI + CI) — следующая фаза цикла 1.7.0 после накопления пользовательского опыта по уже опубликованному RC.

## Реализация (начата)

Реализован pure-решение принятия решений: [TvAutoFailoverPolicy](../app/src/main/java/io/nekohasekai/sagernet/ui/tv/TvAutoFailoverPolicy.kt) (enabled / fallbackOrder / currentHealthy / cooldown / per-session cap) и [тесты](../app/src/test/java/io/nekohasekai/sagernet/ui/tv/TvAutoFailoverPolicyTest.kt). Хранение opt-in и списка профилей: [TvAutoFailoverPreferences](../app/src/main/java/io/nekohasekai/sagernet/ui/tv/TvAutoFailoverPreferences.kt). UI: плитка «Включить автопереключение» в ряду «Подключение» и окно со списком всех профилей и чекбоксами (`MainBrowseFragment.showAutoFailover`). Интеграция решения в runtime (автоматическая смена профиля по событиям здоровья) — следующий шаг реализации; до неё плитка только сохраняет настройку и не меняет подключение.
