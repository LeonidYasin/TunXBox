Почему была остановка и как восстановлено

  • Исходная сборка run 39505780016 успешно выполнила JVM/UI/native/signing/packaging, но завершилась failure только на публикации: git push -f rolling-тега отказал GitHub App без workflows permission для .github/workflows/source-readiness.yml.
  • Это конкретный встроенный GITHUB_TOKEN в Actions, а не доказательство отсутствия прав у всех подключений. Другой trigger того же workflow не добавляет permission. Не добавлять выдуманный permissions: workflows: write в Actions.
  • Существующий авторизованный пользовательский MCP leonid-mcp.duckdns.org/mcp → create_tag создал отдельный annotated v1.6.0-rc.158 на точный проверенный SHA. Старый rolling tag и stable не перемещались.
  • prerelease-from-pr.yml получил явный режим recover_rc158; reusable publish-verified-rc158.yml повторно проверяет исходный run/успех каждого gate, 38 UI test cases, actual tag SHA, неизменность verifier contracts, конкретные APK hashes, реальную подпись/version/ABI и 16KB alignment. Скачивает опубликованные assets и проверяет их до снятия draft. Ни пересборки, ни signing secrets в этом режиме нет.
  • Восстановительная публикация run 39511252702 SUCCESS. Предыдущая попытка 39510852939 упала из-за sdkmanager вне PATH; исправлено абсолютным путём установленного SDK.

Режим recovery одноразовый, жёстко ограничен rc.158; повторный запуск отказывается перезаписывать уже публичный release. Для будущих номеров проектировать отдельный проверяемый процесс, не менять константы без нового аудита. recover_rc158=true — публикующий режим; с check_only=true caller ничего не публикует. Для обновления rolling tag отдельно потребуется корректная авторизация/действие владельца; номерной RC не появится автоматически в нынешнем in-app test updater.

3. Исправления и доказательства

Портретный TV scroll

ui/tv/TvPointerScrollController.kt: touchSlop/axis lock, ровно один CANCEL дочернему горизонтальному пути; вертикальный жест идёт в настоящий outer RecyclerView onTouchEvent с native velocity/fling. Mouse wheel через scroll factor. Pointer mode блокирует focus realignment до D-pad. MainBrowseFragment не возвращает старый фокус от отложенного DB callback; D-pad восстанавливает видимый фокус и не исполняется дважды. Taps/long press/horizontal gestures остаются обычными. Регрессии JVM и реальный instrumentation portraitTvScrollsWithFingerAndMouseThenResumesRemoteWithoutChangingVpn.

Гонка NET_BUSY

group/BoundedConnectionCheck.kt раньше возобновлял continuation до busy=false; мгновенная следующая проверка ошибочно видела занятость. Теперь освобождение после завершения реальной работы, но до resume. Настоящий зависший worker после timeout/cancel по-прежнему BUSY — не разрешать параллельный запуск. Новый детерминированный Unconfined/latch тест падал на старом коде и прошёл на новом (4/4 standalone JUnit17/Kotlin2.0.21/coroutines1.6.4); полные CI JVM tests также прошли.

4. Следующие действия — в порядке

  • Владелец сообщил: смартфон обновился до rc.158 без проблем; портретная прокрутка предварительно работает нормально. Запись приёмки. Модель/Android/ABI/предыдущая версия не сообщены. Это положительная частичная приёмка, не подтверждение всех устройств/мыши/пульта/сохранности всех данных. Оставшаяся матрица портретного TV на реальном смартфоне: swipe/fling вверх/вниз, отпускание без snap-back, wheel/drag мыши, затем D-pad; обычные горизонтальные ряды, tap/long press и VPN/выбранный профиль не меняются сами. Приложить модель/Android/ABI/точную версию и наблюдение, без приватной конфигурации.

  • Разрешить 15 конфликтующих файлов с master отдельным проверяемым integration commit, не через blanket ours/theirs. git merge-tree --write-tree --name-only HEAD origin/master показал конфликты в release workflows, MainActivity/strings, regression/instrumentation tests и docs. Сохранить оба набора сценариев и полные test-name gates, регенерировать docs inventory и заново собрать/протестировать итоговый merge tree. Затем посмотреть все PR checks и последние Source readiness runs. Последний commit обязан иметь свои conclusions; предыдущий passed source job или cancelled run не равен full green.
  • Для #6/#10 выполнить безопасную одинаковую-профиль/сеть/устройство проверку и принять явное fix/defer решение. Не закрывать исходный report только за добавление диагностики.
